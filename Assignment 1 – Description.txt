Tower of Hanoi

Tower of Hanoi (https://en.wikipedia.org/wiki/Tower_of_Hanoi) is a famous problem
involving some number d of disks arranged on some number p of pegs. The disks increase in
size so that disk 2 is larger than disk 1, disk 3 is larger than disk 2, etc., and disk d is larger
than disk (d − 1) (See Fig. 1).

Figure 1: Tower of Hanoi with d = 8, and p = 3. Source: https://commons.wikimedia.org/
wiki/File:Tower_of_Hanoi.jpeg
Initially, all disks are placed on the first peg as shown in the figure, in order 1, 2, . . . , d
(counting from the top downwards). Throughout this assignment, the initial peg is peg 1 and
the final peg is peg p. The aim is to move all of the disks to the final peg through a sequence
of moves, adhering to these rules:
(a)

at each time step, only one disk may be moved from one peg to another (only the topmost
disk on a peg may be moved),

(b)

a larger disk must never be placed on top of a smaller disk.

We will use f (d, p) to denote the minimum number of moves required to transition from the
initial state (where all disks are on the first peg) to the goal state (where all disks are on the
final peg).

State representation. A state is represented as a list of lists, with the disks on each peg
listed in increasing order of size (i.e. the topmost disk first). For example, with d = 3 and
p = 3 the initial state is [[1,2,3], [], []] and the goal state is [[], [], [1,2,3]].
Search conventions (these apply to all of Section 1). Because you are asked to report
the number of expanded states, everyone must count the same way.

states that are only goal-tested.

already appear on the current search path (path-based cycle checking). Do not maintain
a global visited set across iterations for these two algorithms, as this changes the reported
counts. Where a different algorithm is required, the question says so explicitly.
